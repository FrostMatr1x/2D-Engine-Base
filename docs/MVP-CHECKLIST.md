# MVP движка симуляций: честная оценка и чеклист

Дата: 2026-10-10. Оценка для человека, который знает ровно столько, сколько уже написано в проекте
(выбор физического устройства + окно на Silk.NET).

---

## Вердикт

**Сложно, но не из-за концепций, а из-за объёма.** Ни одна отдельная часть MVP не требует знаний, которых
у тебя нет. Проблема в том, что обязательных частей много, и почти все они обязательные — пропустить нельзя.
Плюс обратная связь ужасная: одна неверная строка = чёрный экран без единого сообщения об ошибке.

Реалистично: **35–60 часов сосредоточенной работы** до MVP, где MVP = окно + N инстансированных объектов
с камерой + одна симуляция на фиксированном шаге.

При 1.5 часа за вечер — **5–8 недель**. Первый треугольник (блок 4) — примерно половина всего пути,
и именно там застревает большинство.

**Что снижает оценку:** обязательные validation layers (разница между 40 и 200 часами), готовый референс
для сверки, дисциплина «один шаг — одна проверка».

**Где ты сейчас:** по объёму — 15–20% пути. Причём сделанная часть (перебор устройств, очереди, расширения) —
самая муторная механическая работа, а не самая концептуально тяжёлая. То, что она написана и структурирована —
хороший признак: вопрос не в способностях, а в том, хватит ли терпения на объём.

## Чеклист (делать по порядку, не перескакивать)

Правило: **не начинать следующий пункт, пока текущий не даёт 0 ошибок валидации.**

### Блок 0. Подготовка
- [ ] `sudo dnf install vulkan-validation-layers vulkan-tools`; `vulkaninfo --summary` показывает RTX 4060
- [ ] Валидационный слой виден: `VK_LOADER_DEBUG=all` не ругается на отсутствующий слой
- [ ] Шейдерный тулчейн: `glslangValidator` (пакет `glslang`) компилирует тестовый `.vert` → `.spv`
- [ ] Сборка проекта починена (`using Engine.Graphic.Vulkan;`), `dotnet run` открывает пустое окно

### Блок 1. Instance
- [ ] `VulkanInstance`: `CreateInstance` + app info
- [ ] + `VK_EXT_debug_utils` и debug messenger → **проверка: намеренно сломать код и увидеть VUID-сообщение**
- [ ] Surface через `EngineWindow.CreateSurface`
- [ ] `VulkanContext` хранит vk / instance / surface

### Блок 2. Устройство
- [ ] `CreateDevice` на выбранном `SelectedPhysicalDevice`, очереди graphics + present
- [ ] device / queue / queueFamilyIndices лежат в контексте

### Блок 3. Swapchain (первое настоящее пекло)
- [ ] Формат, present mode, extent, imageCount → `CreateSwapchainKHR`
- [ ] `GetSwapchainImagesKHR` + ImageView на каждый образ
- [ ] Recreate по `FramebufferResize`
- [ ] Recreate по `VK_ERROR_OUT_OF_DATE_KHR` / `VK_ERROR_SUBOPTIMAL_KHR`
- [ ] **Минимизация окна (extent = 0) не крашит** — ждать, не создавать swapchain

### Блок 4. Первый кадр
- [ ] Render pass (1 аттачмент, `Clear`, `Undefined` → `PresentSrcKHR`) + framebuffers
- [ ] Шейдеры, **треугольник захардкожен в вершинном шейдере** — ни одного буфера, ни одного дескриптора
- [ ] Command pool + command buffers
- [ ] Пайплайн: `CullMode.None`, blend `SrcAlpha/OneMinusSrcAlpha`, динамические viewport/scissor
- [ ] Синхронизация: semaphores + fence, **пока 1 кадр в полёте**
- [ ] Acquire → submit → present в цикле
- [ ] 🎯 **ТРЕУГОЛЬНИК НА ЭКРАНЕ** (примерно половина всего проекта пройдена)

### Блок 5. Синхронизация по-взрослому
- [ ] 2 кадра в полёте, fence на кадр, ожидание перед переиспользованием

### Блок 6. Объекты
- [ ] Вершинный буфер + раскладка `{ Vector2 pos; Vector4 color; }`
- [ ] Push constants + ортопроекция (левый верхний угол, Y вниз, пиксели)
- [ ] **Проверка проекции: квад ровно там, где ожидаешь, и не перевёрнут**
- [ ] Инстансированный квад: базовый квад + instance buffer, поворот в шейдере
- [ ] 🎯 100 000 инстансов, стабильные 60+ fps
- [ ] Камера: pan + zoom, корректная конвертация координат мыши в мировые
- [ ] Double buffering instance-буфера (не перезаписывать то, что читает GPU)

### Блок 7. Симуляция
- [ ] Fixed-step loop + интерполяция отрисовки между `prev` и `curr`
- [ ] Одна простая симуляция (движение по полю / boids / n-body)
- [ ] HUD в заголовок окна: `fps / N / step` (без ImGui, без текстур)

### Не входит в MVP
Текстуры · шрифты и текст на экране · ImGui · headless-батч · CSV-экспорт · снапшоты ·
GPU compute · записи в PNG · 3D.

## Топ-6 ловушек (здесь теряют недели)

1. **Чёрный экран без ошибок.** Валидатор молчит, значит проблема логическая: забытый layout transition
   (`Undefined → ColorAttachment → PresentSrc`), неверная ортопроекция, или clear-цвет совпал с фоном.
2. **Краш при сворачивании/ресайзе окна.** `extent` становится `0×0`. Классика — 90% новичков.
3. **Переиспользование семофора до сигнала / отсутствие fence.** Валидатор это ловит и орёт — слушай его.
4. **Silk.NET-специфика:** незаполненные `SType`/`pNext` (часть ставится автоматически — но не вся),
   `unsafe`/`fixed`, время жизни `Vk.GetApi()`. Ошибки тут выглядят как «ничего не работает».
5. **Перезапись буфера/образа, который ещё читает GPU.** Симптом — мерцание и мусор, а не краш.
6. **Порядок освобождения при выходе.** Падение при закрытии окна после успешного рендера — тоже классика.

## Как понять, что застрял

Если на одном пункте чеклиста сгорело **два вечера** — не долби дальше. Откатись до последнего зелёного
состояния, сверься с референсом построчно, проверь, что валидатор реально включён (легко забыть, что он молчит,
потому что слой не загрузился — и ты неделю отлаживаешь вслепую).

* `vulkan-tutorial.com` — C++, но концептуально переносится 1:1 на Silk.NET (типы и порядок вызовов совпадают,
  отличается только обёртка). **Важно:** сайт сам теперь предупреждает, что устарел и рекомендует

  ещё самый разжёванный.

  после паузы будет больно (а ты именно этого и хочешь — возвращаться).

## Честная развилка

Если цель — **«свой движок, который живёт и используется для симуляций»**, то Vulkan здесь покупает
контроль и знание, но платится 40–60 часами до MVP и плохой отладкой.

* **OpenGL (Silk.NET.OpenGL)** — тот же свой движок, те же шейдеры, та же математика, но MVP за 5–10 часов,
  и почти вся энергия уходит на симуляцию, а не на плумбинг.
* **Veldrid** — низкоуровневая абстракция с Vulkan-бэкендом: остаёшься «почти на Vulkan», но swapchain,
  синхронизацию и render pass берёт на себя.

Если же цель — **понять Vulkan** (а «мне нужен собственный движок» звучит именно так), то путь правильный,
просто закладывай 2 месяца вечеров, а не «на выходных допилю».
